# 布局系统设计说明

本文是 `packages/ui/src/layouts` 的实现规格和维护边界，不是使用教程。使用者接入、示例教程和故障排查见 `packages/ui/src/layouts/README.md`；包级说明见 `packages/ui/README.md`。这里只描述当前代码的事实来源、模块职责、公共契约和内部算法。

## 1. 设计目标

布局系统的目标是把应用壳能力做成一个可复用 Vue 布局模块：

- 普通页面只通过 `route.meta.layout` 选择布局，不在页面组件里判断 header、sidebar、footer。
- 菜单、面包屑、固定页签、已访问页签从路由树和当前路由派生。
- 自定义区域组件统一只接收 `{ context }`，不把 sidebar、settings、route 等能力拆成散 props。
- 状态入口唯一，外部依赖只通过 `Layout['Context']` 进入。
- 内部渲染层只消费解析后的 `RenderContext`，不重复读取原始路由 meta 或外部 Store。
- 公共 API 少而稳定：运行时入口是 `LayoutRuntime`，类型入口是 `Layout`，高频路由模块声明只额外提供 `LayoutRouteModule` 短类型。

## 3. 公共出口

`packages/ui/src/layouts/index.ts` 当前公共出口必须保持为（包内使用相对路径；由 `packages/ui/src/index.ts` 再导出）：

```ts
import type { Layout } from './types/public'

export { default as AppLayout } from './components/App.vue'
export { default as LayoutSettings } from './components/common/settings/context/Content.vue'
export { default as LayoutSettingsTrigger } from './components/common/settings/Trigger.vue'
export { LayoutRuntime } from './runtime/api'
export type { Layout } from './types/public'

export type LayoutRouteRecord = Layout['Route']['RecordRaw']
export type LayoutRouteModule = LayoutRouteRecord[]
```

应用与示例只从 **`@tauri-vue-template/ui`** 导入上述符号，例如：

```ts
import { AppLayout, LayoutRuntime } from '@tauri-vue-template/ui'
import type { Layout, LayoutRouteModule } from '@tauri-vue-template/ui'
```

约束：

- 不导出内部组件，例如 `AreaOutlet`、`NavigationMenu`、`HeaderLayout`。
- 不导出 `types/internal.ts` 中的渲染类型。
- 导出 `LayoutSettingsTrigger`。默认设置入口由布局系统内部 addon 注入；需要把同一个设置入口放到 sidebar、footer 或业务自定义区域时，可作为 addon 组件复用，并通过 props 传入调用方声明的 `to`。
- 导出 `LayoutRouteRecord` 和 `LayoutRouteModule`。它们只是 `Layout['Route']['RecordRaw']` 的短类型别名，用于路由模块声明处获得 IDE 提示，不新增第二套路由契约。
- 新增公共能力时优先挂到 `LayoutRuntime` 或 `Layout[...]` 分组路径；只有像路由模块数组这种高频书写场景，才允许提供短类型别名。
- `@tauri-vue-template/ui` 的 `package.json` 仅导出 `"."` → `./src/index.ts`；不对外暴露 `./layouts/*` 子路径。布局子目录内的相对 import 是包内实现细节。

## 4. 公共类型契约

`types/public.ts` 只导出 `Layout` 一个类型根入口。业务侧统一使用对象路径；路由模块数组可以使用入口导出的短类型别名：

```ts
import type { Layout, LayoutRouteModule, LayoutRouteRecord } from '@tauri-vue-template/ui'

type RouteRecord = LayoutRouteRecord
type RouteModule = LayoutRouteModule
type AreaProps = Layout['Area']['Props']
type TabsContext = Layout['Tabs']['Context']
```

`LayoutRouteRecord` 等价于 `Layout['Route']['RecordRaw']`，`LayoutRouteModule` 等价于 `LayoutRouteRecord[]`。这两个别名只隐藏重复类型路径，不改变公共路由契约。

关键类型事实：

| 类型路径 | 当前含义 |
| --- | --- |
| `Layout['Name']` | `'topnav' / 'sidebar' / 'hybrid' / 'blank'` |
| `Layout['StandardName']` | 标准布局名，不含 `blank` |
| `Layout['Area']['Mode']` | `false / 'default' / 'custom' / 'auto'` |
| `Layout['Area']['Declaration']` | 区域模式或区域配置对象 |
| `Layout['Area']['Preset']` | 区域预设，只包含 `settings/header/sidebar/content/footer`，不包含 `name/areas/fixed` |
| `Layout['Config']` | 完整 layout 对象，包含 `name`、`areas`、`settings`、`fixed`、四个大区 |
| `LayoutRouteRecord` | 入口导出的单条布局路由记录短类型 |
| `LayoutRouteModule` | 入口导出的路由模块数组短类型 |
| `Layout['Context']` | 外部依赖入口：`routes`、`settings`、`areas`、`tabs` |
| `Layout['Route']['Meta']` | 布局层消费的路由 meta |
| `Layout['Tabs']['Context']` | 外部页签 adapter |

注意事项：

- 区域声明不支持直接写组件函数。组件必须写在 `{ component }` 中。
- addon 不支持直接写组件函数。addon 必须是 `{ component, props?, class?, label? }`。
- `true` 不是合法区域模式。启用默认内容使用 `'default'`，自适应用 `'auto'`。
- `layout.fixed` 只属于完整 layout 对象，不放在 route meta 顶层；字符串 `blank` 和未显式声明 `fixed` 的 blank 对象由运行时视为默认 fixed，完整对象可用 `fixed: false` 显式取消。
- `Layout['Area']['Context']['area']` 由 `AreaOutlet` 补齐，根 `context` 在进入区域前没有 `area` 字段。

## 7. Runtime API

`runtime/api.ts` 暴露 `LayoutRuntime`：

```ts
export const LayoutRuntime = {
  create: createLayouts,
  defineRoutes,
  defineContent,
  defaultState: defaultLayoutState,
  context: {
    get: getDefaultContext,
    use: useContext,
    set: setDefaultContext,
  },
  tabs: {
    clear: clearTabs,
  },
} as const
```

语义：

- `create(options)` 创建 Vue 插件，安装时读取一次 `options.context`。
- `defineRoutes(options)` 根据模块导出生成根布局路由。
- `defineContent(component)` 返回 `{ default: component, 'layout-content': component }`。
- `context.get(routes?)` 读取默认 context，没有自定义 context 时构造内置 context。
- `context.use(routes?)` 先读组件树注入的 context，再回退默认 context。
- `context.set(context)` 设置全局默认 context。
- `tabs.clear()` 只清理内置 tabs。

不要在文档或代码中再使用旧命名 `provide`、`inject`、`setDefault`、`getDefault`。

## 8. Context 和内置状态

`runtime/context.ts` 管理内置 context。

内置状态：

- `builtInState` 来自 `structuredClone(defaultLayoutState)`。
- 初始化时读取 localStorage 中的 preferences。
- `watch()` 只持久化 `builtInState.preferences`。
- localStorage key 为 `${VITE_STORE_KEY_PREFIX || 'layouts'}:layouts:preferences`。

偏好合并规则：

- 按层合并 `theme`、`navigation.sidebar`、`navigation.topnav`、`pageElements`。
- 旧持久化数据缺字段时不覆盖新增默认字段为 `undefined`。
- 读取和写入失败都静默跳过；写入失败在开发环境 `console.warn`。

内置 tabs：

- `visitedTabs` 保存已访问页签。
- `cachedTabs` 保存 `KeepAlive` include 列表。
- `visibleTabs` 过滤 `/redirect`。
- `cachedTabSet` 从 `cachedTabs` 派生。

内置 `addRouteView(route)` 忽略：

- `/redirect` 路由。
- `meta.hidden` 路由。
- 没有 `meta.title` 的路由。

页签去重键是 `routeNavPath(route)`，不是当前实际 `route.path`。这是为了让可选参数路由复用同一个导航页签。

## 9. 路由辅助

`runtime/routes.ts` 只保留两个降低使用复杂度的 helper。

`defineContent(component)`：

```ts
export function defineContent<const T extends Layout['Area']['Component']>(component: T) {
  return {
    'default': component,
    'layout-content': component,
  }
}
```

`defineRoutes(options)` 默认值：

| 字段 | 默认值 |
| --- | --- |
| `publicRouteKeys` | `['publicRoutes']` |
| `routeExportSuffix` | `'Routes'` |
| `root.path` | `'/'` |
| `root.name` | `'root'` |

收集规则：

- `publicRouteKeys` 命中的数组放在根布局外。
- 其他以 `routeExportSuffix` 结尾的数组放入根布局 `children`。
- 根布局 `component` 固定为 `AppLayout`。
- 根布局 `children` 固定为收集结果，调用方不能覆盖。

## 10. Layout 解析

`utils/layout.ts` 把 `Layout['Declaration']` 解析成 `ResolvedLayout`。

默认布局：

| layout | header | sidebar | content | footer |
| --- | --- | --- | --- | --- |
| `blank` | `false` | `false` | `default` | `false` |
| `topnav/sidebar/hybrid` | `default` | `default` | `default` | `auto` |

子区默认：

- `sidebar.footer` 是 `auto`。
- `content.before` 是 `auto`。
- `content.after` 是 `auto`。
- 其他子区默认是 `default`。

标准布局默认会调用 `withSettings(defaultHeader('default'))`，把 `SettingsTrigger` 注入到 `header.right.addons.after`。

解析顺序：

```txt
defaultLayout(name)
  -> applyPreset(areas)
  -> applyLayout(routeLayout)
```

`areas` 支持字符串或字符串数组。数组按声明顺序合并，后者覆盖前者。缺失 preset 只在开发环境警告。

`resolveLayout(input, registry, overrideName, fixed)` 规则：

- `overrideName` 来自 `preferences.layoutMode`，只允许 `topnav/sidebar/hybrid`。
- `fixed=false` 时，`overrideName` 会覆盖当前路由解析出的布局名称；如果 `input` 是对象，只替换 `name`，保留 `areas/settings/header/sidebar/content/footer` 等局部声明。
- `fixed=true` 时完全尊重当前路由声明，不使用用户布局偏好覆盖。
- `fixed` 由 `useRuntime()` 从当前 `route.meta.layout` 派生：字符串 `blank` 固定；完整对象按 `layout.fixed ?? layout.name === 'blank'` 计算，因此 `{ name: 'blank', fixed: false }` 会显式取消 blank 的默认固定。

## 11. 区域合并

合法区域模式：

```ts
false | 'default' | 'custom' | 'auto'
```

`toAreaConfig(input)`：

- `undefined` 表示不覆盖。
- 合法模式值转成 `{ mode: input }`。
- 配置对象原样进入合并。
- 组件函数不是合法 `AreaDeclaration`，不会被当成 `{ component }`。

`mergeArea(base, override)`：

- 没有 override 时复制 base。
- `override === false` 时 mode 设为 `false`，清空 component 和 addons。
- 有 `component` 且没有显式 `mode` 时，mode 默认为 `custom`。
- `class`、`label`、`component` 覆盖同级字段。
- `addons.before` 和 `addons.after` 分别合并；传 `false` 清空继承项。

`mergeRegion(base, override, name)`：

- 先提取整区自己的 `mode/component/class/label/addons`。
- 再按 `regionParts[name]` 合并子区。
- `all` 作为所有子区的默认覆盖。
- 显式子区声明优先于 `all`。
- 只声明子区不会自动把整区 mode 改成 `custom`。

`mergeHeader()` 的额外规则：

- `header: false` 会移除默认设置入口。
- 非对象 header 声明会保留默认设置入口。
- layout 对象中的 `settings: false` 会关闭默认设置入口；传入字符串会保留入口并把设置触发器改为调用方声明的路由跳转；需要更多触发器参数时可写对象形式；其他情况保留默认打开内置设置面板。

## 12. 区域来源和 AreaOutlet

`utils/area.ts` 和 `components/common/AreaOutlet.vue` 共同决定最终区域渲染。

命名视图解析：

- `resolveNamedView(route, name)` 从 `route.matched` 末端向前查找。
- 子路由命名视图覆盖父路由命名视图。

主体自定义来源包括：

- 显式 slot。
- 路由命名视图。
- `layout` 配置中的 `component`。

addons 是区域附加内容，不参与主体来源优先级，但会触发区域挂载。`mode=false` 必须同时压住主体来源和 addons。

`shouldRender(config, sources, options)`：

1. `mode=false` 返回 `false`。
2. 有主体自定义来源或 addons 返回 `true`。
3. `mode='default'` 返回 `true`。
4. `mode='auto'` 返回 `options.autoDefault ?? true`。
5. `mode='custom'` 返回 `options.customPlaceholder ?? true`。

`AreaOutlet` 主体来源优先级：

```txt
slot custom -> route named view -> config component -> default slot
```

完整渲染顺序：

```txt
addons.before -> 主体内容 -> addons.after
```

`AreaOutlet` 会向区域 context 注入：

```ts
area: {
  name,
  label: config.label,
  mode: config.mode,
  region,
  part,
}
```

`region` 和 `part` 从 `layout-*` 名称推导。

## 13. useRuntime

`composables/useRuntime.ts` 是 AppLayout 的唯一运行时派生入口。

输入：

```ts
useRuntime(props: Layout['App']['Props'], slots: Record<string, unknown>)
```

输出：

```ts
{
  runtime: ComputedRef<RenderContext>
}
```

来源优先级：

```txt
props.context ?? injected context ?? getDefaultContext(defaultRoutes)
```

主要派生：

- `settings` 从 context 读取。
- `routes` 从 `toValue(context.routes)` 读取。
- `areas` 从 `context.areas ?? {}` 读取。
- `tabs` 从 `context.tabs` 读取。
- `layoutInput` 从当前 `route.meta.layout` 读取。
- `fixed` 从 `layoutInput` 派生；对象读取 `layout.fixed ?? layout.name === 'blank'`，字符串 `blank` 默认固定。
- `layout` 由 `resolveLayout(layoutInput, areas, settings.preferences.layoutMode, fixed)` 得到。
- `menu` 由 `displayMenu(menuItems(routes))` 得到。
- `title` 来自当前 `route.meta.title`，缺失时是 `App`。

主题副作用：

- `theme.mode` 为 `dark` 时添加 `dark` class。
- `theme.mode` 为 `light` 时移除 `dark` class。
- `theme.mode` 为 `system` 时跟随 `(prefers-color-scheme: dark)`。
- 每次同步会移除全部 `themeColors`，再添加当前主题色。
- 无 `document` 时跳过。

侧边栏规则：

- 真实状态只有 `settings.ui.sidebar.mode`。
- `collapsed`、`hidden`、`visible` 都从 mode 派生。
- `collapseMode='auto'` 在移动端映射为 `hidden`，桌面端映射为 `rail`。
- 移动端 `toggle()` 在 `hidden` 和 `expanded` 间切换。
- 桌面端 `toggle()` 在 `collapsed` 和 `expanded` 间切换。
- 进入移动端且当前 expanded 时自动 close。
- 回到桌面端且当前 hidden 时自动 expand。

路由变化副作用：

- 调用 `tabs.value?.addRouteView(route)`。
- 移动端关闭侧边栏。
- watch 对 `route.fullPath` immediate 执行。

## 14. RenderContext

`types/internal.ts` 中 `RenderContext` 是内部组件共享对象：

```ts
interface RenderContext {
  context: Layout['Area']['Context']
  layout: ResolvedLayout
  routes: RouteRecordRaw[]
  settings: Layout['State']
  tabs?: Layout['Tabs']['Context']
  navigation: RenderNav
  elements: RenderElements
  page: RenderPage
  shell: RenderShell
}
```

内部组件只能读这个对象，不再各自重复解析 route meta、settings 或 routes。

`runtime.shell` 包含：

- `isStandardLayout`
- `shouldRenderHeader`
- `shouldRenderSidebar`
- `shouldRenderFooter`
- `renderSidebarAsRail`

footer 是可选区域：标准布局下默认 `auto` footer 不渲染空底栏；整区或任一子区存在主体自定义来源、addons、`custom` 占位或显式 `default` 时才渲染。

## 15. AppLayout

`components/App.vue` 职责：

1. 声明 `Layout['App']['Props']`。
2. 声明全部区域 slots。
3. 调用 `useRuntime(props, slots)`。
4. 根据 `runtime.shell` 组合 sidebar、header、content、footer 和 settings dialog。
5. 转发显式 slots 到对应内部区域组件。

AppLayout 不做：

- 不直接解析 layout。
- 不直接生成菜单。
- 不直接操作 tabs。
- 不直接依赖业务 Store。

slots 清单：

```txt
default
header
header-left
header-brand
header-center
header-right
sidebar
sidebar-header
sidebar-content
sidebar-footer
content-before
content-after
footer
footer-left
footer-center
footer-right
```

所有 slot props 都是：

```ts
{ context: Layout['Area']['Context'] }
```

骨架：


## 17. 菜单和路由派生

`utils/menu.ts` 负责纯派生：

- `joinPath()` 归一化子路由路径。
- `navPath()` 去掉可选参数段，例如 `/chat/:sessionId? -> /chat`。
- `routeNavPath()` 从 matched 链最近可展示项推导当前导航路径。
- `menuItems(routes)` 从路由树生成菜单树。
- `displayMenu(items)` 处理 `hideChildrenInMenu` 和单子级提升。
- `breadcrumbs()` 从 matched 链生成面包屑，必要时用当前 route title 兜底。
- `affixItems()` 从完整路由树收集固定页签。

菜单规则：

- `hidden` 路由直接返回空数组，子级不会继续上浮。
- 无 `title` 的中间路由不上菜单，但可展示子级会上浮。
- 菜单排序按 `order` 升序，再按中文标题排序。
- 父级仅一个子级且没有 `alwaysShow` 时提升子级。
- 父级有 `hideChildrenInMenu` 时隐藏子菜单。

## 18. 内容出口

`content/index.vue` 规则：

- `content.before` 和 `content.after` 默认 `autoDefault=false`，无自定义来源不渲染空区域。
- 主内容区默认渲染一个带 padding 的 section。
- 当前路由有 `meta.iframeSrc` 时渲染 iframe。
- 没有 iframe 时渲染 `RouterView`。
- `keepAlive(viewRoute)` 在存在 tabs adapter 时以 `cachedViewSet` 或 `cachedViews` 为准。
- 没有 tabs adapter 时回退 `viewRoute.meta.keepAlive`。
- `cacheKey` 优先来自 `viewRoute.meta.cacheKey`，否则使用 `viewRoute.fullPath`。

## 19. 设置系统

设置系统分两层：

- `settings/index.vue` 是对话框容器，负责 Teleport、遮罩、关闭、焦点恢复和焦点循环。
- `settings/context/Content.vue` 是可复用内容，公共导出名是 `LayoutSettings`。

`Content.vue` 只重置 `preferences`，不重置 `ui.settings.open` 和 `ui.sidebar.mode`。

设置项直接修改传入的 `Layout['State']`，不引入内部 Store。

## 20. 维护检查清单

修改该模块后至少检查：

- 公共导出是否仍与 `index.ts` 一致。
- README 是否只讲使用教程，设计说明是否只讲实现规格。
- 区域模式、addon 形态、context API 是否与 `types/public.ts` 和 `runtime/api.ts` 一致。
- 布局固定策略是否仍只通过 `layout.fixed` 表达，且 `blank` 默认 fixed 的规则在 README、设计说明和示例中一致。
- 新增区域或子区是否同步 `types/regions.ts`、组件、README 和设计说明。
- 新增 route meta 是否同步 `Layout['Route']['Meta']`、菜单或内容出口逻辑、README。
- 新增状态是否明确放入 `preferences` 或 `ui`，并同步默认状态和设置面板。
- 旧 API 名、旧导出名、旧文档示例是否残留；扫描时应覆盖导出名、context 方法名、区域模式、组件快捷写法和 addon 快捷写法。

验证建议：

- 文档改动至少运行 Markdown 检查。
- 类型或示例签名改动至少运行相关 TypeScript 检查。
- UI 区域渲染改动需要浏览器验证 header、sidebar、content、footer、settings、mobile sidebar。
