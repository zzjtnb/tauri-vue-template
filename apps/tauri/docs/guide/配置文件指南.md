# Tauri 配置文件标准指南

本文定义 `apps/tauri` 当前 Tauri 配置文件的唯一正确维护方式：默认 Tauri 配置指向“示例”应用，桌面发布产物只保留 macOS `.dmg`、Windows NSIS `.exe`、Linux `.deb`。

## 命令执行目录

`android:*`、`ios:*`、`mac:*`、`harmony:*`、`tauri:*` 等脚本**只**定义在 `apps/tauri/package.json`。根 `package.json` 没有这些脚本，因此在仓库根直接执行 `pnpm android:build` 会报 `Missing script`（与鸿蒙、iOS 相同，没有平台例外）。

### 方式 A — 在 `apps/tauri` 目录内

```bash
cd apps/tauri
pnpm android:build
pnpm ios:build
pnpm harmony:build
```

平台接入文档里的步骤列表、检查清单若写 `pnpm android:*` / `pnpm ios:*` / `pnpm harmony:*`，**默认指方式 A**。

### 方式 B — 在仓库根目录

```bash
pnpm --dir apps/tauri android:build
pnpm --dir apps/tauri ios:build
pnpm --dir apps/tauri harmony:build
```

等价写法：

```bash
pnpm --filter @tauri-vue-template/tauri android:build
```

多应用目标的前端 dev/build 仍优先使用 `pnpm --filter @tauri-vue-template/cli tauri:target -- …`（见根 `README.md`）。

## 核心原则

1. **`src-tauri/tauri.conf.json` 是当前唯一默认 Tauri 配置**。
   - 直接运行 `tauri dev`、`tauri build`、`mac:build`、`windows:build`、`linux:build` 时读取它。
   - 当前默认应用是“示例”，不是“模板”。
2. **当前不维护平台专属配置文件**。
   - 不保留 `src-tauri/tauri.macos.conf.json`、`src-tauri/tauri.windows.conf.json`、`src-tauri/tauri.linux.conf.json`、`src-tauri/tauri.android.conf.json`、`src-tauri/tauri.ios.conf.json`。
   - 平台字段直接写在 `src-tauri/tauri.conf.json` 的 `bundle.macOS`、`bundle.windows`、`bundle.linux`、`bundle.android`、`bundle.iOS` 中。
   - 只有未来出现不能放进主配置的长期平台差异时，才重新引入平台专属配置文件。
3. **构建变体使用显式 `--config`**。
   - 临时 Beta、企业版、渠道包可以传入额外配置文件或 JSON 字符串。
   - `--config` 不替代当前默认配置，也不能写入真实 secret。
4. **敏感材料不写入配置文件**。
   - 证书、私钥、keystore 密码、Apple 凭据、updater 私钥密码只能来自本机安全存储或 CI secret。
5. **字段名和产物类型必须和当前脚本一致**。
   - macOS：`--bundles dmg`，发布产物 `.dmg`。
   - Windows：`--bundles nsis`，发布产物 `.exe`。
   - Linux：`--bundles deb`，发布产物 `.deb`。

## 1. 当前项目配置文件地图

| 文件 | 职责 | 当前规则 |
| --- | --- | --- |
| `package.json` | Tauri CLI 脚本、Rust 检查脚本、平台入口脚本 | 只作为 `apps/tauri` 打包器入口，不承载前端业务源码 |
| `src-tauri/tauri.conf.json` | Tauri 默认主配置 | 当前默认指向“示例”应用，并包含桌面和移动端可提交默认值 |
| `src-tauri/Cargo.toml` | Rust crate、Tauri Rust 依赖、插件依赖 | Rust 入口和插件注册的依赖来源 |
| `src-tauri/Cargo.lock` | Rust 依赖锁定 | 必须随 Rust 依赖变化同步 |
| `src-tauri/capabilities/*.json` | Tauri v2 权限声明 | 新增插件或前端调用能力时必须同步权限 |
| `src-tauri/gen/*` | Android、iOS、OpenHarmony 生成工程 | 由 Tauri CLI 或平台工具生成，不能手写平行工程 |
| `src-tauri/icons/*` | Tauri 图标资源 | 只维护当前配置真实引用的图标文件 |

## 2. 当前默认 Tauri 主配置

默认配置文件固定为：

```text
src-tauri/tauri.conf.json
```

当前默认应用是“示例”，关键字段如下：

```json
{
  "productName": "示例",
  "version": "0.1.0",
  "identifier": "com.zzjtnb.examples",
  "build": {
    "frontendDist": "../../examples/dist",
    "devUrl": "http://localhost:3000",
    "beforeDevCommand": "pnpm --dir ../.. --filter @tauri-vue-template/examples dev",
    "beforeBuildCommand": "pnpm --dir ../.. --filter @tauri-vue-template/examples build"
  },
  "app": {
    "windows": [
      {
        "title": "示例",
        "width": 800,
        "height": 600,
        "resizable": true,
        "fullscreen": false
      }
    ]
  },
  "bundle": {
    "active": true,
    "targets": ["dmg", "nsis", "deb"]
  }
}
```

项目修改规则：

- `build.devUrl` 必须和默认前端应用的开发服务器端口一致。
- `build.frontendDist` 必须指向默认前端应用的构建产物目录。
- `build.beforeDevCommand` 只启动默认前端应用的开发服务器。
- `build.beforeBuildCommand` 只构建默认前端应用的生产产物。
- `identifier` 是平台包名和签名体系基础，发布后不要随意更改。
- `app.security.csp` 修改时必须同时考虑开发端口、HMR WebSocket、接口代理和生产资源来源。
- `bundle.icon` 只维护真实存在且被当前配置引用的图标资源。

## 3. 配置文件格式

本项目标准格式是 JSON：

```text
src-tauri/tauri.conf.json
```

Tauri 支持 JSON5 和 TOML，但本项目当前不启用对应 feature，也不维护多套平行主配置。

如未来切换格式，必须同轮更新：

1. `Cargo.toml` 中的 Tauri 配置格式 feature。
2. 实际配置文件名。
3. 本目录下所有配置示例。
4. 平台接入指南和发布指南。

## 4. 平台配置边界

当前项目把可提交的平台默认值写在主配置内，不维护独立平台配置文件。

| 平台 | 当前配置入口 | 当前发布产物 |
| --- | --- | --- |
| macOS | `bundle.macOS` | `.dmg` |
| Windows | `bundle.windows` | NSIS `.exe` |
| Linux | `bundle.linux` | `.deb` |
| Android | `bundle.android` | `.apk` / `.aab` |
| iOS | `bundle.iOS` | Xcode archive/export 结果 |

### macOS

```json
{
  "bundle": {
    "targets": ["dmg"],
    "macOS": {
      "minimumSystemVersion": "10.13",
      "hardenedRuntime": true,
      "signingIdentity": null,
      "providerShortName": null,
      "entitlements": null
    }
  }
}
```

规则：`signingIdentity`、`providerShortName`、`entitlements` 默认保持 `null`，避免模板默认触发不可用证书或不存在的 entitlements 文件。正式发布时再按签名指南接入 Apple 证书、公证和 staple 流程。

### Windows

```json
{
  "bundle": {
    "targets": ["nsis"],
    "windows": {
      "digestAlgorithm": "sha256",
      "certificateThumbprint": null,
      "timestampUrl": "http://timestamp.digicert.com",
      "tsp": false,
      "allowDowngrades": false,
      "webviewInstallMode": {
        "type": "downloadBootstrapper",
        "silent": true
      },
      "nsis": {
        "installMode": "currentUser",
        "displayLanguageSelector": true,
        "compression": "lzma"
      },
      "wix": null,
      "signCommand": null
    }
  }
}
```

规则：当前 Windows 只发布 NSIS `.exe`。`certificateThumbprint` 和 `signCommand` 默认保持 `null`，正式发布时再接入 Authenticode 证书。

### Linux

```json
{
  "bundle": {
    "targets": ["deb"],
    "linux": {
      "deb": {
        "section": "utils",
        "priority": "optional"
      }
    }
  }
}
```

规则：当前 Linux 只发布 `.deb`。DEB 的仓库签名、包索引签名或外部分发签名由发行渠道处理。

### Android

```json
{
  "bundle": {
    "android": {
      "minSdkVersion": 24,
      "versionCode": 1000
    }
  }
}
```

规则：Android release keystore、alias、密码由 Gradle、Android Studio 或 CI secret 管理，不写入 Tauri 配置。

### iOS

```json
{
  "bundle": {
    "iOS": {
      "minimumSystemVersion": "14.0",
      "bundleVersion": "1",
      "developmentTeam": null
    }
  }
}
```

规则：模板不硬编码个人 Apple Team。真机构建、TestFlight 或 App Store Connect 发布时，通过本机 Xcode 或 CI secret 提供 Team、证书、profile 和 App Store Connect API key。

## 5. `--config` 临时覆盖

Tauri CLI 支持通过 `--config` 传入额外配置文件或 JSON 字符串。适用场景：

- Beta、staging、enterprise 构建。
- 临时覆盖 `productName` 或 `identifier`。
- 临时替换 updater endpoint。
- 不想长期提交到主配置的打包实验。

示例：

```json
{
  "productName": "示例 Beta",
  "identifier": "com.zzjtnb.examples.beta"
}
```

保存为：

```text
src-tauri/tauri.beta.conf.json
```

构建时显式传入：

```bash
pnpm tauri build --config src-tauri/tauri.beta.conf.json
```

项目规则：

- `--config` 用于构建变体，不替代默认主配置。
- 长期存在的构建变体必须写入文档，说明覆盖字段和发布渠道。
- 不把真实 secret 写进 `--config` 文件。

## 6. `Cargo.toml` 标准

`src-tauri/Cargo.toml` 是 Rust / Cargo 清单文件，用于声明 Rust crate 依赖和构建依赖。

项目规则：

- 不要只更新 `Cargo.lock` 而不确认 `Cargo.toml` 是否表达了真实版本线。
- `tauri` 的 `features = []` 通常由 Tauri CLI 根据配置管理，不手动堆叠无关 feature。
- Tauri 依赖更新时同步 npm 包、Cargo manifest、Cargo lock 和相关文档。

依赖更新流程见：

```text
apps/tauri/docs/guide/Tauri依赖更新指南.md
```

## 7. `package.json` 脚本边界

当前 `apps/tauri/package.json` 的桌面脚本边界：

```text
pnpm mac:build      # 在 macOS host 生成 .dmg
pnpm windows:build  # 在 Windows host 生成 NSIS .exe
pnpm linux:build    # 在 Linux host 生成 .deb
```

规则：

- 平台脚本只作为对应 host 的标准入口，不代表可以跨 host 构建所有平台安装包。
- 修改平台构建脚本时，必须同步对应平台接入指南。
- 不把前端业务源码脚本塞进 `apps/tauri`；前端构建通过 Tauri 配置里的 `beforeDevCommand` / `beforeBuildCommand` 委托给对应前端应用。

## 8. capabilities 权限配置

Tauri v2 权限配置位于：

```text
src-tauri/capabilities/
```

项目规则：

- 新增插件时，必须同步对应 capability 权限。
- 桌面端、移动端、OpenHarmony 的权限差异不要混在一个文件里硬凑。
- 权限按最小可用原则声明，不为了省事开放无关能力。
- 前端调用 Tauri API 报 permission denied 时，优先检查 capability，而不是改业务代码兜底。

## 9. 生成目录和原生工程配置

移动端和平台生成目录位于：

```text
src-tauri/gen/
```

项目规则：

- Android 工程由 `pnpm android:init` 或 Tauri CLI 维护。
- iOS 工程由 `pnpm ios:init` 或 Tauri CLI 维护。
- OpenHarmony 工程按本项目 OpenHarmony 接入文档维护。
- 不手写平行的 Android、iOS、OpenHarmony 工程目录。
- 生成目录中的平台签名配置不能写真实密码或私钥明文。

## 10. 修改配置前检查清单

修改配置前必须确认：

- [ ] 这个字段属于 Tauri、Cargo、pnpm、capability 还是平台原生工程。
- [ ] 是否应该写入主配置，还是需要新增长期平台专属配置文件。
- [ ] 是否是临时构建变体，是否更适合 `--config`。
- [ ] 是否包含 secret、真实证书、真实私钥、本机绝对路径或局域网 IP。
- [ ] 修改 `build.devUrl` 时是否同步默认前端应用端口。
- [ ] 修改 `beforeDevCommand` / `beforeBuildCommand` 时是否同步前端应用脚本。
- [ ] 新增插件时是否同步 Rust 依赖、前端依赖、plugin 初始化和 capability 权限。
- [ ] 修改 Tauri 依赖版本时是否同步 npm 包、Cargo manifest 和 lock 文件。
- [ ] 修改平台签名配置时是否同步 `apps/tauri/docs/guide/签名与更新签名指南.md`。
- [ ] 修改平台构建脚本时是否同步对应平台接入指南。

## 11. 验证命令

配置变更后按范围验证：

```bash
pnpm tauri:info
pnpm rust:check
```

涉及平台构建时，只在对应 host 执行对应脚本：

```bash
pnpm mac:build
pnpm windows:build
pnpm linux:build
pnpm android:build
pnpm ios:build
```

无法在当前 host 验证的平台，必须在结果中明确写出未验证原因。
