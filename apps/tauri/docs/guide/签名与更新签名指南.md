# Tauri 签名与更新签名标准指南

本文定义本项目各平台安装包签名、移动端签名和 updater 更新包签名的统一标准。签名材料只能来自开发者本机证书库、系统 keychain、Android keystore、Apple Developer 账号、CI secret 或平台后台；不要把真实私钥、证书密码、keystore 密码、App Store Connect API key、Windows 证书私钥提交进仓库。

## 核心原则

1. **平台安装包签名和 updater 签名是两套体系**。
   - macOS、Windows、iOS、Android、Linux 分发渠道签名决定安装包或应用本体是否被平台或渠道信任。
   - Tauri updater 签名决定更新包是否被 Tauri updater 插件信任。
2. **真实密钥只通过本机系统或 CI secret 注入**。
   - 配置文件只保存非敏感开关、路径约定和公开标识。
   - 私钥、密码、证书内容、keystore 内容不写入仓库。
3. **每个平台只使用 Tauri 或平台工具链支持的入口**。
   - macOS 使用 Tauri `bundle.macOS` 和 Apple notarization 环境变量。
   - Windows 使用 Tauri `bundle.windows` 或 `signCommand`。
   - iOS 使用 Tauri `bundle.iOS`、Xcode project 同步和 Apple 环境变量。
   - Android release signing 使用 Gradle / Android Studio / CI 注入。
   - Linux 当前只发布 `.deb`，仓库签名、包索引签名或外部分发签名由发行渠道处理。
4. **发布构建必须能复现签名来源**。
   - CI 中记录使用哪个证书标识、哪个 profile、哪个 keystore 别名、哪个 export method。
   - 不记录 secret 明文。

## 1. macOS 安装包签名

Tauri macOS 签名入口来自 `bundle.macOS`：

```json
{
  "bundle": {
    "macOS": {
      "signingIdentity": "Developer ID Application: Example Company (TEAMID)",
      "hardenedRuntime": true,
      "providerShortName": "TEAMID",
      "entitlements": "Entitlements.plist"
    }
  }
}
```

字段说明：

| 字段 | 作用 | 是否敏感 |
| --- | --- | --- |
| `signingIdentity` | 指定 codesign 使用的证书 identity | 否，但依赖本机 keychain 中的私钥 |
| `hardenedRuntime` | 是否启用 hardened runtime，默认 true | 否 |
| `providerShortName` | notarization provider short name | 否 |
| `entitlements` | entitlements 文件路径 | 否，但内容要按能力最小化 |

CI 可用环境变量：

```text
APPLE_CERTIFICATE
APPLE_CERTIFICATE_PASSWORD
APPLE_ID
APPLE_PASSWORD
APPLE_TEAM_ID
APPLE_API_KEY
APPLE_API_ISSUER
APPLE_API_KEY_PATH
```

Tauri 行为边界：

- 设置 `--no-sign` 时跳过签名。
- 存在 `APPLE_CERTIFICATE` / `APPLE_CERTIFICATE_PASSWORD` 时，Tauri 从环境变量导入证书。
- 存在 `signingIdentity` 时，Tauri 从系统 keychain 查找 identity。
- 存在 notarization 凭据时，Tauri 会执行 notarization；否则跳过公证并给出 warning。
- `.dmg` 也会在可签名条件满足时被签名。

## 2. Windows 安装包签名

Tauri Windows 签名入口来自 `bundle.windows`：

```json
{
  "bundle": {
    "windows": {
      "digestAlgorithm": "sha256",
      "certificateThumbprint": "CERT_SHA1_THUMBPRINT",
      "timestampUrl": "http://timestamp.digicert.com",
      "tsp": false
    }
  }
}
```

字段说明：

| 字段 | 作用 | 是否敏感 |
| --- | --- | --- |
| `digestAlgorithm` | 文件摘要算法，默认 fallback 为 `sha256` | 否 |
| `certificateThumbprint` | 证书 SHA1 thumbprint，用于 signtool 查找证书 | 否，但依赖证书私钥存在于证书库 |
| `timestampUrl` | 时间戳服务地址 | 否 |
| `tsp` | 是否使用 RFC 3161 Time-Stamp Protocol | 否 |
| `signCommand` | 自定义签名命令，`%1` 会被替换成待签名文件 | 否，但命令使用的 secret 不能写入仓库 |

默认签名依赖 Windows SDK 的 `signtool.exe`。需要指定 signtool 路径时使用：

```text
TAURI_WINDOWS_SIGNTOOL_PATH
```

非 Windows host 交叉签名时使用 `signCommand`，例如接入 `osslsigncode`：

```json
{
  "bundle": {
    "windows": {
      "signCommand": {
        "cmd": "osslsigncode",
        "args": ["sign", "-certs", "cert.pem", "-key", "key.pem", "-in", "%1", "-out", "%1.signed"]
      }
    }
  }
}
```

上例只展示占位结构；真实证书和私钥路径必须由 CI secret 或构建环境提供。

Tauri 行为边界：

- 有 `certificateThumbprint` 或 `signCommand` 才进入 Windows signing。
- 没有签名配置时，NSIS `.exe` 仍可构建，但不满足正式发布要求。
- `--no-sign` 会跳过签名。

## 3. iOS 签名

iOS 签名入口分为 Tauri 配置、Xcode project 同步和环境变量三层。

Tauri 配置字段：

```json
{
  "bundle": {
    "iOS": {
      "developmentTeam": "TEAMID",
      "bundleVersion": "1",
      "minimumSystemVersion": "14.0"
    }
  }
}
```

`developmentTeam` 也可以通过环境变量覆盖：

```text
APPLE_DEVELOPMENT_TEAM
```

CI 可用证书和 profile 环境变量：

```text
IOS_CERTIFICATE
IOS_CERTIFICATE_PASSWORD
IOS_MOBILE_PROVISION
```

App Store Connect API 签名 / 导出相关环境变量：

```text
APPLE_API_KEY
APPLE_API_ISSUER
APPLE_API_KEY_PATH
```

Tauri 行为边界：

- `developmentTeam` 会同步为 Xcode `DEVELOPMENT_TEAM`。
- `IOS_CERTIFICATE` / `IOS_CERTIFICATE_PASSWORD` 会导入 iOS 证书。
- `IOS_MOBILE_PROVISION` 会解析 provisioning profile，并同步 `PROVISIONING_PROFILE_SPECIFIER`。
- `--export-method` 会写入临时 `ExportOptions.plist`。
- 真机、TestFlight、App Store Connect 不能依赖空签名配置。
- 模拟器验证可以使用 `--no-sign`。

常用构建：

```bash
pnpm tauri ios build -t aarch64-sim --no-sign
pnpm tauri ios build -t aarch64 --export-method release-testing --ci
pnpm tauri ios build -t aarch64 --export-method app-store-connect --ci
```

## 4. Android release 签名

Tauri 官方 Android 模板不在 `app/build.gradle.kts` 中默认生成 release `signingConfigs`。Android release signing 属于 Gradle / Android Studio / CI 发布链路。

标准 secret 来源：

```text
ANDROID_KEYSTORE_PATH
ANDROID_KEYSTORE_PASSWORD
ANDROID_KEY_ALIAS
ANDROID_KEY_PASSWORD
```

推荐 Gradle 结构：

```kotlin
val releaseKeystore = System.getenv("ANDROID_KEYSTORE_PATH")

android {
    signingConfigs {
        create("release") {
            storeFile = releaseKeystore?.let { file(it) }
            storePassword = System.getenv("ANDROID_KEYSTORE_PASSWORD")
            keyAlias = System.getenv("ANDROID_KEY_ALIAS")
            keyPassword = System.getenv("ANDROID_KEY_PASSWORD")
        }
    }
    buildTypes {
        getByName("release") {
            signingConfig = signingConfigs.getByName("release")
        }
    }
}
```

项目边界：

- 不把 keystore 文件提交进仓库。
- 不把 keystore 密码写进 Gradle 文件。
- 没有 release signing secret 时，`pnpm android:build` 只能作为构建验证，不作为正式发布验收。
- AAB 通常用于商店上传，APK 用于本地安装和测试分发。

## 5. Linux 签名

本项目当前 Linux 发布产物只保留 `.deb`。DEB 的信任链通常由发行渠道处理，例如仓库签名、包索引签名或外部分发签名。

行为边界：

- `pnpm linux:build` 只生成 `.deb`。
- `.deb` 本身不在当前 Tauri 配置中写入真实签名私钥或密码。
- 如果通过 Debian 仓库分发，由仓库发布流程负责签名和索引。
- 如果通过普通下载分发，由外部分发渠道负责校验、签名或哈希发布。

## 6. OpenHarmony / HarmonyOS HAP 签名

OpenHarmony / HarmonyOS 签名入口来自 Hvigor `build-profile.json5` 的 `signingConfigs`：

```json5
{
  app: {
    signingConfigs: [
      {
        name: "default",
        material: {
          storeFile: "signature/OpenHarmony.p12",
          storePassword: "Hvigor 加密值",
          keyAlias: "OpenHarmony Application Release",
          keyPassword: "Hvigor 加密值",
          signAlg: "SHA256withECDSA",
          profile: "signature/examples-profile.p7b",
          certpath: "signature/OpenHarmonyApplication.pem"
        }
      }
    ],
    products: [
      {
        name: "default",
        signingConfig: "default"
      }
    ]
  }
}
```

项目签名材料目录：

```text
src-tauri/gen/ohos/signature/
```

边界：

- `storePassword` / `keyPassword` 必须是 DevEco / Hvigor 可解密的加密值。
- 加密值必须与 `signature/material/` 成套维护。
- 测试签名材料只能用于开发验证；正式发布必须替换成发布证书、发布 profile 和对应 material。
- HAP 签名和 Tauri updater 签名不是同一套签名体系。

## 7. Tauri updater 签名

Updater 签名独立于平台安装包签名。启用 updater artifact：

```json
{
  "bundle": {
    "createUpdaterArtifacts": true
  }
}
```

签名命令和环境变量：

```bash
pnpm tauri signer generate
pnpm tauri signer sign ./release/apps/examples/v0.1.0/macos/updater/示例.app.tar.gz
```

最小签名命令形态：

```bash
pnpm tauri signer sign <更新包文件路径>
```

`<更新包文件路径>` 要替换成真实 updater 更新包文件。例如当前 release 目录下的 updater 包：

```bash
pnpm tauri signer sign ./release/apps/examples/v0.1.0/macos/updater/示例.app.tar.gz
pnpm tauri signer sign ./release/apps/examples/v0.1.0/windows/updater/示例.nsis.zip
```

实际发布时必须通过环境变量提供 updater 私钥和密码；密码只允许通过 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` 注入，不能写进命令参数、脚本或日志。

CI 中推荐通过 secret 注入私钥路径或私钥字符串，例如：

```bash
TAURI_SIGNING_PRIVATE_KEY_PATH=~/.tauri/examples.key \
TAURI_SIGNING_PRIVATE_KEY_PASSWORD='<password>' \
pnpm tauri signer sign ./release/apps/examples/v0.1.0/macos/updater/示例.app.tar.gz
```

```text
TAURI_SIGNING_PRIVATE_KEY
TAURI_SIGNING_PRIVATE_KEY_PATH
TAURI_SIGNING_PRIVATE_KEY_PASSWORD
```

边界：

- `<更新包文件路径>` 指向 Tauri updater 更新包文件，不是 `.dmg`、`.exe`、`.deb`、`.ipa`、`.apk` 等平台代码签名入口。
- updater 私钥不能提交进仓库。
- updater 公钥可以进入 updater 配置或后端发布配置。
- 平台安装包已签名，不代表 updater 包已签名。
- updater 包已签名，不代表 macOS / Windows / iOS / Android 平台会信任安装包。

## 8. 发布验收矩阵

| 平台 | 本地构建可通过 | 正式发布还需要 |
| --- | --- | --- |
| macOS | `.dmg` 生成 | Developer ID 签名、hardened runtime、公证、staple |
| Windows | NSIS `.exe` 生成 | Authenticode 签名、timestamp |
| iOS | 模拟器 `.app` 或 archive | Team、证书、provisioning profile、export method |
| Android | APK / AAB 生成 | release keystore 签名 |
| Linux | `.deb` 生成 | 仓库签名、包索引签名或外部分发签名 |
| OpenHarmony / HarmonyOS | HAP 生成 | 发布证书、发布 profile、Hvigor material 成套签名 |
| Updater | artifact 生成 | updater 私钥签名和更新清单签名字段 |

## 9. 禁止事项

- 不提交 `.p12`、`.p8`、`.jks`、`.keystore`、私钥 PEM 或密码文件。
- 不在 `tauri.conf.json` 中写真实密码。
- 不在 Gradle 文件中写真实 keystore 密码。
- 不把 `TAURI_SIGNING_PRIVATE_KEY` 写入仓库或文档示例的真实值。
- 不用 `--no-sign` 产物作为正式发布产物。
